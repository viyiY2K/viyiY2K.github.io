网络环境

先说网络环境，科学养鹅是基操了。但怎么养也是有区别的，有些朋友用的梯子还是古早的一键直连…那可真不知道背后的节点到底是否干净了。

这种 VPN 软件，底层逻辑不难理解，一般是根据域名去把我们本机的流量中转到，像是美国或者其他节点的服务器上，然后再去访问那些我们原本在国内不能访问的网站。于是像 YouTube 这类网站，最终看到会是节点的 IP，而不是我们自己的真实 IP。

一键直连的软件客户端，把节点管理、协议配置、线路切换之类的东西抽象掉了，只有 on/off，那网络出口的 IP 地址是更难被用户控制的。Clash 这种代理客户端， 可以把控制权交还给用户，节点透明度更高也更便于我们去模拟外区土著。

所以，如果你还在用一键直连的 VPN 软件，那么首先，你需要一个独立于客户端的节点机场。我惯用的是 FlowerCloud，费用根据情况波动，有每年 128 和每月 39/58/113 的档位套餐。按需选择之后，可以按教程下载配置好 Clash（因为我自己用的这个，后面也是按这个来的）。

一个小 Tips，付款前可以看下教程文档里挂着的优惠码，如果你点了我的 FlowerCloud 推广链接，我好像也许大概可能会拿到些什么，你也会有优惠的样子，具体我也不清楚（刚开通👉👈），哪个划算你用哪个就行，两个好像也可以叠加。

ISP 购买

现在我们就拥有了一个可以自行选择节点调整配置的 VPN 工具，那我们想要模拟说，我就是在外区的一个正常的普通用户，是需要一个外区的静态住宅宽带（ISP Proxies），作为节点去中转本机网络连接的。

为什么原本机场的节点不能用呢？因为这个机场里的节点很可能不止你一个人在用，你也不知道其他人有没有使用过这个节点去注册 Claude，而很可能有人这么干过且被封号了，那么这个节点就很容易被标记为异常。

仅你使用的节点显然比多人使用的机场节点更干净，至于静态和动态的区别，则在于出口 IP 是否变化。动态住宅 IP 可能造成地理位置、网络环境不一致，显然不利于我们伪装成土著，谁家好人天天闪现不同城市呀。

ISP 购买的地区要和注册、付款的账号地址匹配，后续我们会使用 Apple 账户或者 Google play 账户付款，所以如果你已经有美国或者日本的 Apple ID，可以优先考虑购买同地区账户避免麻烦。因为之后用到的所有账号和设置，都必须保持账号地区的一致性。

有看到攻略说每个月 60 元以上的 ISP 比较靠谱，但本穷咖还是买了朋友之前推荐的 IPRoray，1 个日本的 0 欺诈 ISP 每个月不到 50 元这样。

当然，IPRoray 只保证当前租期内的独占，不保证过去租期内的不良记录，而且高级版的零欺诈风险也不能完全排除风险，但这已经是很高性价比的选择了。

也有更贵的 zorocloud 可以考虑，价格在 108~138/月，据说纯净度更高，但我还没试过（等我下次被封号再试吧（希望不要有下次（希望我永远用不上🙏。

总之，抄作业可以去 IPRoray 上注册完账户，在「我的订单」里点击「ISP」，接着点「创建新的订单」。

接着确认勾选的是 30Days，把代理数量改成 1，地区看你情况。有苹果美区 ID 可以优先买美国，没有建议买日本，因为物理距离近，延迟会比较低。欺诈评分等级选高级版，也贵不了多少，买个心安。

接着付完款，我们就拥有了一个相对干净的节点。

先插播一个简单科普。

像 FlowerCloud 这种机场呢，其实相当于打包卖多个节点套餐的服务商，这样你看哎这个日本 A 节点连不上不行，咱换一个 B 节点就行。或者你就是想用美国节点看 YouTube，日本节点看 Instagram，那也可以根据域名来做分流。

Clash 这种客户端呢，其实是独立于机场的，你可以买不同的机场套餐，导入进 Clash 就是不同的配置，它只是一个方便你去切换节点和网络配置的工具。不论你机场换了几家，我 Clash 自巍然不动。

比如说我本机向 YouTube 发起了一个网络请求，那大概就是 本机 -> Clash -> Clash 中选中的对应节点 -> YouTube 这么个流程。

如果你只考虑在网页版使用 Cluade，那么买完 ISP 节点之后，就可以跳过 Clash 配置（这个主要是为了 Claude 桌面端和 Claude Code 的使用），到下一节「注册环境」的部分。

Clash 配置

现在我们拥有了一个 ISP 节点，本质上和机场提供的那些节点没太大区别，自然也可以修改我们本机的 Clash 配置，把这个节点加上。

通常机场给的配置里也是做了分流，YAML 文件里会首先会把已知国内域名单独走 DIRECT，还有一些 PT 下载、广告代理等流量单独处理，毕竟这种没必要走海外代理，既占流量额又延迟高。然后针对常用的国外域名，再去分组写规则，比如先按地区分个代理组，然后根据网站域名去选这个代理组。这样网站可以单独选地区，地区的代理组里又可以根据延迟切换节点。最后，如果一圈儿匹配下来，域名还是没命中，就交给 Final 组去兜底。

我们要做的呢，大致过程是先在配置里加上 ISP 节点，然后把 AI 相关的域名（尤其是 Claude）分流到 ISP 节点里，接着把兜底的 Final 组也接到 ISP 上。这样就算 AI 组里没有涵盖到 Anthropic 使用的第三方服务调用，也会落到 Final 组里。

我的自用配置做得更精细一点，单独给分了个 ISP 节点组，里面放了 1 个二跳节点和 2 个直连节点。这样如果直连节点延迟高 ，可以切换成用机场节点做了桥接的二跳节点，通常来说这个会更快一点，但重复占流量额度是次选。

我也没有简单粗暴地反向让所有海外流量都走 ISP 节点，毕竟机场节点流量可以和 ISP 节点流量分开计算，ISP 可以仅供 Claude 和其他 AI 使用，日常看 YouTube 之类的用机场流量更合适。

所以，我把 Claude 写死在了 ISP 组里，其余 AI 相关域名默认选 ISP 组，如果 ISP 节点流量不足或者延迟过高，可以切换成别的机场节点，毕竟其他家没有 A 社封号狠。其余的常用网站依旧保留可选的机场节点组，而不是固定 ISP 组。

好好好，我造有人已经看不明白了。总之，总之，你可以把我的这份脱敏配置（戳這裡下載）给到你的 Codex，然后把下方的 Prompt 复制粘贴发给它。

请参照附件中的 Clash 脱敏配置，使用我自己的机场节点和 ISP 节点，生成一份新的 Clash 配置，并作为独立配置导入我的 Clash 客户端。

目标：
复现参考配置中的代理链、策略组、分流规则和 DNS 设置，同时适配我的节点和客户端。

具体要求：

之后去 IPRoray 里点击「复制代理」，到时候方便 Codex 读剪切板使用。

之后在 Clash 切换 Codex 写好的配置，理論上應該和我的代理分組一樣。

Proxies 是所有節點的大分組，也是我們 JP-ISP-Chain 的前跳節點。像我圖上，在 Proxies 裡選擇了「專線 6」，那 Chain 實際的網絡請求鏈路就是「本幾 Claude 客戶端 -> 專線 6 -> ISP -> Anthropic」，最終 A 社看到的出口地址仍然是 ISP，前跳只是為了加速。

ISP 這個分組裡，另外兩個是直連的節點，只是端口和連結方式不一樣，本質沒什麼區別。這三個節點的出口依舊都是同一個 IP。如果某個 timeout，切換另一個就可以。分流規則裡，Claude 相關的已經寫死選定 ISP 組，以防誤操作。

AI 組是命中的就是除了 Claude 之外的常規 AI，比如 OpenAI 相關的流量會走 AI 組選中的節點出。這個可以單獨固定走美區，不和 ISP 綁定死。

Final 組是所有分流規則失效的兜底，默認是保持在 ISP 組防止洩漏真實 IP。但如果有時候訪問國內域名確實非常之卡無法加載，可以把這個短暫切到 DIRECT，用完再切回來。

可以再簡單測試一下，分别访问 baidu.com、Openai.com 和 anthropic.com。首先這仨應該都能正常訪問，其次看 Clash 的日志，应该分别是 DIRECT 和代理组里对应选中的节点。

要用 Codex 改是因为涉及科学养鹅，国内的 Agent 不太安全。理论上你用网页版的 ChatGPT 改也可以，只需要手动把 YAML 文件粘贴进 Clash（ISP 信息也是需要手动填，毕竟我的 Prompt 要求禁止明文提供）。不让 Codex 去验证是因为如果你用比较差的模型，如果配置写岔了它会反复重连卡住。

手动验证的时候如果出现海外网站打不开或者分流不对的情况，那就切回原有配置，让 GPT 老师再改。之前确实有用 Sol 改不对的情况…最后是直接上 Astra 了🚬。

如果你用的不是 Clash，也可以把我之前的模板给它，這個模板主要是看分流規則和節點分組，让它根据你用的代理软件去改配置。最简单的其实是你下载一个 Clash，通常机场也会提供 Clash 的适配。

anyway，总之，到这一步，网络配置就成功了一大半。日常使用上，勾选上 Clash 的开机自启常驻，开启 TUN 虚拟网卡模式。

至于是规则还是全局呢……建议是全局，但我的 mac mini 平常也挂了采集国内社媒数据的定时，担心国内社媒账号被风控，所以我是选「规则」，目前帳號還健在。

一般来说大家也只有一台主机，日常还是要用国内的软件，全局可能会延迟比较高，如果能接受当然是全局更安全。如果長期開全局，記得首頁的節點要選對，一般會默認是 Proxies 裡的，修改成我們預期的 ISP 節點即可。

后续如果账号使用和氪金都正常，建议是不要随便切换 ISP 节点，如果你全程抄作业到这里，那应该是只续了 30 天，要记得提前几天去 IPRoyal 里续费 ISP。在「我的订单」-「ISP」里下滑到最下面 ，选中对应的订单，点击「动作」列的「…」，选择「延长订单」即可。

兜底熔断

最后我们在网络环境这部分要做的工作，是确保 Clash 崩溃之后 Claude 也不会拿到真实 IP，那这个就要设置防火墙级别的 Kill Switch 了。

我手上的都是 macOS 设备，用本机的 PF 搞定就行，把这段 Prompt 发给你的 Codex。

我的核心目标是：

在不改变现有 Mac 使用习惯的前提下，给 Clash 增加一道独立的网络安全防线，防止 Clash 意外崩溃时，Claude Code 和 Claude Desktop 绕过代理，暴露我的真实公网 IP。

一、我现在的环境

我已经完成了正常情况下的代理配置：

* 使用 Clash Verge Rev 和 Mihomo 内核。
* 开启 TUN 模式，接管系统网络流量。
* 配置了分流规则，国内流量直连，海外流量通过代理。
* 为 Claude Code 和 Claude Desktop 配置了专用 ISP 出口。
* 正常运行时，Claude 应该通过指定的 ISP IP 与海外服务通信，而不是使用我本地的真实 IP。

我现在不是要解决如何配置代理的问题，而是要解决代理失效后会发生什么的问题。

二、我真正担心的风险

Clash 正常工作时，一切都没有问题。

但假设某天 Clash 突然崩溃、进程退出，或者 TUN 意外失效。

这时，macOS 可能自动恢复使用本机的默认网络路由。

Claude Code 和 Claude Desktop 并不知道 Clash 已经崩溃，可能继续尝试连接 Anthropic 的服务器。

即使这些连接因为国内网络限制而最终失败，连接尝试本身仍然可能从我的真实公网 IP 发出。

而且 Claude Code 可能调用 Git、Node、curl 或 MCP 等子进程，所以我担心的不只是 claude 这个进程本身。

我想消除的，就是 Clash 失效后流量自动回落到真实网络出口的风险。

三、我希望达到的效果

场景	预期行为
Clash 正常运行	国内直连，海外走代理，Claude 使用专用 ISP
Clash 意外崩溃	国内应用继续正常联网
Clash 意外崩溃	海外连接直接被阻断，不允许回落真实出口
Clash 重新启动	恢复之前的代理和分流方式
Mac 正常使用	不需要切换用户、改变工作流或额外管理应用

我不要求在 Clash 崩溃后继续访问海外互联网。

我完全可以接受海外服务全部断网，只要国内网络保持正常。

四、我对解决方案的要求

我希望尽量使用现有工具，不增加复杂度。

因此，我倾向于：

* 继续使用 Clash 负责日常代理和分流。
* 使用 macOS 自带的 PF 作为独立于 Clash 的防火墙。
* 不使用 LuLu 等第三方软件。
* 不创建独立 macOS 用户。
* 不改变 Claude Code 和 Claude Desktop 当前的运行方式。
* 尽可能实现常驻防护，而不是等 Clash 崩溃后才检测并拦截。

我愿意牺牲的是：Clash 故障期间的海外网络访问能力。

我不愿意牺牲的是：国内网络的可用性，以及现有的 Mac 使用体验。

五、用一句话概括

我想给 Mac 做一个只针对海外网络的 Kill Switch：Clash 活着，国内直连、海外走代理；Clash 死了，国内照常联网、海外立即断网，绝不让 Claude 因为代理失效而通过真实 IP 直连。

这里还有一个技术上的区别：我真正关心的是防止真实出口泄漏，而不是简单地让海外网站打不开。因此，最终的方案不仅要阻断非国内 IP，还要验证 DNS、IPv6、代理上游例外及其他可能的绕行路径。

Windows 暫時沒試過，可以把 Prompt 裡的 macOS 換成 Windows 嘗試看看，目標定義清楚的話，應該只有實現方式可能不太一樣，效果可以類似。

起初加這個是因為，我發現我的同事們的操作習慣其實是，只在用到外網的時候才開 Clash，而不是常駐。在未開啟 Clash 的時候，很可能後台還有其他 Claude 相關服務在運行，那真實出口 IP 依舊會暴露⋯⋯

如果 Kill Switch 正常兜底，那麼在 Clash 退出的情況下，Claude 相關的網絡請求會直接在 DNS 解析階段就掛掉，慣例防一手 again。

至此，网络配置上能做的防护基本已经做完了。

如果再封号，能在网络配置上做的事情，就只有清除相关信息换一个更干净的 ISP 节点，或者干脆自己搭一个 VPS。再往上升级，就是干脆租一台在美国或者日本的 macmini 远程使用了🚬（希望我不要被逼到这一步）。

注册环境

像我这个 IP 如果已经被检测到过有滥用记录，其实多多少少在注册初期的风险值就更高。据推特上各路佬的说法，Claude 的风控是积分制，注册伊始就定下了权重，基本只减不增。

IP 的干净程度是第一位，除了网络之外，浏览器也可能透露的位置，这也同样要是受支持的地区。其次是邮箱，这个我们后面说，先把浏览器配好。

浏览器指纹

使用比特浏览器主要是保证浏览器环境稳定，是的网络稳定不代表你的真实 IP 一定不泄漏。比如最容易导致泄露的 WebRTC，在惯用的浏览器里因为考虑到有时候确实是涉及到音视频传输，一刀切禁用不现实。那不如干脆单独给 Claude 配一个浏览器，并且把浏览指纹清理干净。

这个配置也不复杂，进入官网下载页，下载安装比特浏览器。

点击「浏览器窗口」的「新建窗口」，设置里「代理方式」保持默认的「自定义代理」，「代理类型」选 Socks5。

切去之前的浏览器里打开 IPRoray，注意把协议切换成「SOCKS5」（端口和 HTTP 不一样，别偷懒），然后点击「复制代理」。

粘贴到比特浏览器设置里的「代理主机」这一行，回车会自动填入接下来三行（代理端口、代理账号、代理密码）所需信息。

这里其实比特浏览器本身是做了一次本机代理桥接到 ISP 节点的，所以在你本机的 Clash 分流里，比特浏览器的前跳节点注意不要又弄成 ISP 了，很容易报错。这个一般如果你之前按照我的配置文件模板去修改的 Clash 配置，分流规则会和我的保持一致，默认是用 Proxies 组里的节点，就没啥问题。

浏览器内核版本选稳定版的 146 ，而不是默认最新开发版 148，有可能会导致注册不成功，所以 146 版本优先。

语言地区可以跟随 IP，或者手动改成你的 ISP 对应的语言和时区，一样的没区别。

WebRTC 和地理位置一定要选择「禁止」。

其他选项保持默认，接着点击「一键随机生成指纹配置」，然后「确认」即可。

到这里浏览器的部分就处理好了，我们接着往下推。

浏览器操作

建议是不要使用 Claude 浏览器插件，浏览器太容易暴露信息。如果是涉及 Computer use 的操作，可以通过让 Claude 指挥 Codex 来操控浏览器的，如果需要可以把下面的 Prompt 加入到 CLAUDE.md 里。

#浏览器操作

- 用户是残障人士，不方便操作浏览器。网页上要点、要填、要确认的事（包括 GitHub、飞书后台这类要登录的设置页），一律交给 Codex 在 Chrome 里做，不写成步骤让用户自己去点。只有 Codex 也过不去的本人身份确认，才请用户做，而且只请他做这一步。
- 小事用内置浏览器自己做：本地 UI 的预览和验收、看页面效果、读文档或网页、截图核对、几步点击就能做完的检查。
- 复杂的交给本地 Codex 应用：多步骤或端到端的流程、要登录账号的后台、跨多个网站、耗时长或要反复尝试的；内置浏览器做着做着变复杂了也转交。Chrome 插件已关闭，需要真实浏览器和登录状态的都走 Codex。
- 用法：codex-browser "完整的任务描述"；同一会话追加指令用 codex-browser --resume <会话ID> "追加指令"，会话 ID 在输出末行；可能超过几分钟的放后台运行。Codex 每轮结束会关掉标签页，所以每次都写清网址、步骤和要带回什么（截图存到哪个路径）。

规则怪谈

除此之外呢，还有一些推特上流传出来的规则怪谈，大多是社群汇总无法考证。放在这里仅供参考。

  • 只在同一台终端、同一网络环境中频繁使用 Claude，尽量减少多端登录。
  • 使用 CLI 和 Desktop 都可以，Desktop 似乎会少量加分，尽量少用网页端，最好只保留手机端和 Desktop 登录。
  • 不要一上来就氪金最高档，从免费版逐步升档，尽可能让自己的所有操作看起来像真实用户。
  • 尽量少关联账号，避免暴露的可能性。可以将数据导出成文件，让它读取分析。
  • 不要提供点赞或点踩的按钮，整个聊天记录将会发送给 Anthropic 用于训练。
  • 每个周期不要全部跑满额度，偶尔留个20%左右，建议 Pro 档先跑一段时间。
  • 升级 Max 大概率会直接进入观察期，除非是积分特别多的高权重号。观察期内有减分行为，大概率会封号。
  • 不要将国内网站的链接作为 Prompt 输入，可以把链接里的信息内容用国内 AI 刷一遍抽象纯文本再作为 Claude 输入。
  • 模型正常拒绝回答、系统拦下输出时，不要有意反复索取，也不要反复重新问同一个问题。
  • 时区和语言基本不减分，或仅极少量减分。在工作时间使用不会扣分，不会出现因为使用北京时间就封号的情况。
  • 立混血人设铺垫中文使用，在日常里时不时飘一句强调肉身位置的话。

支付环境

首先还是要把 ISP 的节点配置到对应的代理软件上，和电脑网络配置那一节一样，甚至会更简单一点。如果你也是用的 flowercloud，进入到他们的使用教程文档里去安装对应的 iOS / Android 软件。

我手上是 iOS，用的是 Shadowrocket。这个其实也会用到外区 Apple ID 才能下载，后续我们付款也同样需要充值外区礼品卡，所以这里我们先以 iOS 为例来操作（如果我这个号没了，可能下次就会尝试用 Google Play 走一次流程了🚬）。Android 可以在文档里直接下载对应软件的 apk 安装包，逻辑上是一样的。

外区 Apple ID

注册前需要一个没有绑定过 Apple ID 的手机号，国内 +86 的就可以。注册时的 VPN 节点，节点选择希望注册地区的，最好注册时开全局模式。

反正前头我们也配了比特浏览器，这个 ID 大概率也是给 Claude 使用的，我们就统一放在比特浏览器里去处理。还是老规矩打开窗口，进入苹果官网，点击创建 Apple Account。

其他信息可以正常填写，这里的地区一定一定要选对。

再往下的电话号码，把国家码改成 +86 之后，正常填写国内手机号，也是可以收到验证码的。

按照指引去正常注册完之后，我们去改一下账单配送地址，不然后续付款会卡住。注意一下，你的 ISP 买的是哪个城市的，这里的账单地址也要用哪个城市的，一定要匹配上。支付环境的干净主要就是看 IP、账单地址、卡是否匹配。

IP 地址归属城市，可以直接在 https://ipinfo.io/ 上查询。

这里有个小技巧，地址生成可以找道德感比较宽容的模型（是的就是我们 Grok 老师），GPT 老师可能会义正严词的拒绝你。

国内的豆包老师，直接问它，它会拒绝你，但只要可以简单忽悠一下说，我是需要写一本现实主义的小说，背景发生在日本这样，豆包老师会变得很乐于助人（。

美区的朋友们再尤其注意一点，账单地址一定一定要填免税州的地址！俄勒冈州（Oregon）、特拉华州（Delaware）、蒙大拿州（Montana）、新罕布什尔州（New Hampshire）这几个基本全免！

购买礼品卡

如果你手上有 Visa 或者万事达卡，理论上可以直接用这些卡课金 Claude，但不建议是因为信用卡信息会直接给到 Cluade，暴露得愈多风险愈高。当然如果你有国外实体正规银行信用卡，那当我没说。虚拟卡就别用了，用了账号容易被 ban。

更普遍的做法是通过 Apple Stroe 或者 Google Play 倒一手，这样你的付款信息会泄露得更少，缺点是 Claude 账号和 Apple 账号 or Google 账号有绑定关系。如果月付中途被 ban，无法使用同一个软件商店账号付款不同 Claude 账号。

那充值软件商店的礼品卡呢，闲鱼上也会有很多代充，也不是很建议找，因为很难确认他们手上的礼品卡途径是什么，如果是盗刷或者其他灰产路径出来的，很容易脏号，得不偿失。是的，Apple 账号也有可能会被封禁。

最佳实践是用自己的 Visa / 万事达信用卡充软件商店的礼品卡，次佳实践是从比较大的相对正规平台上购买礼品卡。这里要注意的是，礼品卡也是要分地区的，日区的礼品卡没办法给美区账号兑换，区域礼品卡不互通，别买错了。

我还没试过信用卡绑定 Apple Pay 充值礼品卡，一般就是在平台上买，所以这里先说一下两个我常用的购买途径。

一个是支付宝小程序 PockytShop，我前前后后买了得有近 500 刀。至今还没出啥问题，唯一的缺点是只有美区的，而且有时候容易缺货。

手机打开支付宝，地区切换到旧金山。

搜 PockytShop 小程序，搜不到就复制 https://www.wmslz.com/s/im6sPmr93b1 到浏览器打开再跳转，还不行就扫下面的码。

这里以 Apple 礼品卡演示，Google Play 也是类似。

我们选择「Apple Store & iTunes USA」或者「Apple Gift Card US」，购买对应金额。

接着回到右下角的「订单」，复制礼品卡号码就 ok 啦。

另一种方法是去 SEAGM 平台上买，遇到小程序上缺货或者是日区账号，就来这里。放个传送门：

  • Apple 礼品卡美区：https://www.seagm.com/zh/apple-gift-card-us
  • Apple 礼品卡日区：https://www.seagm.com/zh/itunes-gift-card-japan
  • Google Play 礼品卡美区：https://www.seagm.com/zh/google-play-gift-card-united-states

购买的时候注意一下地区和币种，地区是中国，币种最好是 CNY，这样可以直接使用支付宝付款。修改方式很简单，点击右上角的图标去改下就行。

之后就是注册后绑定手机号，正常去选对应区域的礼品卡，美区日区不通用，再强调一次，不通用啊。以日区 ID 举例，Claude Pro 按月来算是 3000 日元，这个税是含在里面了不用单独扣，所以不用多买。

购买等一会，订单完成后，在「我的卡密」这里点击展示卡片。会看到序列号和卡密，复制卡密就行~

礼品卡兑换

首先我们去手机上切换一下账号，在「设置」里点顶部最上方的卡片「Apple 账户」，然后找到「媒体与购买」里退出当前的账号。

注意这里不要退错了，尤其是你的外区 ID 不是自己注册而是购买的情况，不要退成你手机整个的 Apple 账号，不然很容易锁机。正常这里的流程，是要再点两次的退出登录。

切换完之后，Apple 账户的页面，是不同一个邮箱。切到 App Store 里，界面的语言会更换，下方也会多出一个 Arcade 的分页。

接着我们来兑换卡密。

进入 App Store，点击右上角头像，接着点击「兑换代码」。

选择手动输入兑换码，把之前我们复制的卡密粘贴进去，点击「兑换」即可。

兑换完成之后，付款之前，我们再确认一次「账单寄送地址」。有时候 Apple 账户的 App Store 和网页同步不及时。美区的朋友二次确认是不是免税州，日区的朋友看眼有没同步。

手机网络配置

考虑到我们只是临时在手机上充值，不是常驻使用，就不需要像电脑那样搞那么复杂的分流规则。单独把节点加进去，临时开个全局就行。

进入 Shadowrocket 点击右上角的加号，把类型改成「Socks5」填入对应的地址、端口、密码和用户名，注意这里 Socks5 的端口 IPRoray 一般默认是 12324。

看清楚复制的时候是不是复制成 HTTP/HTTPS 的端口 12323 了，类型和端口要保持一致。其他保持默认就可以。

如果你手机上有导入机场的配置，也可以在「代理转发」这里选一个前跳节点。之后点击右上角保存即可，回到主页之后可以顺手做一次「连通性测试」，看下延迟情况。

没问题之后，把全局路由改成「代理」，关闭「启用回退」，选中我们刚刚添加的ISP 节点，然后开启 VPN 代理。

之后去手机浏览器输入 https://ipinfo.io/json 确认一下 IP 和城市是不是和 ISP 对应的，没问题之后，我们就可以打开 Claude 丝滑登录了。

Claude 正式充值

等等，我知道你很急，但你先别急。

在正式充值之前呢，我们先检测一下当前账号状态，这个大概是十月左右推上传出来的方式。

据说，「Claude 升级的时候付款人的信息（姓名、账单地址、IP 信息、环境信息)以及卡 BIN 信息等都会参与到风控核验。先是 Stripe 的风控核验评估，一种情况是直接拒绝，没有下文。一种是能过，有风险，Stripe 会把结果传给 Claude，Claude 可能就直接封号退款。还一种是能过，风险低，这种才是升级成功。」

首充或者升级 Max 之前简单测一下，惯例防上一手。步骤如下：

访问一下 https://claude.ai/api/organizations 来获取自己的 UUID。

复制 UUID 之后，替换进这个 URL 里 https://claude.ai/api/organizations/【UUID】/kyc_status 。

可以看到我这个账号的状态是 not_required，也就是说该账号升级不需要 KYC，一般直接课金问题不大。其他可能出现的其他状态如下：

  • pending：需要 KYC，正在审核中
  • approved/verified：KYC 已通过，可以升级
  • denied：KYC 被拒，无法升级

只能说非 not_required 的朋友都谨慎课金吧，现在退款成功率不高。

手机开全局检测 IP 地址匹配 ISP + UUID 查询为 not_required 的情况下，基本可以直接手机打开 Cluade 去升级 Pro，Apple 账户中如果有礼品卡余额会默认扣除的，步骤我就不说明了（主要还是忘记截图步骤了。

恭喜你终于用上了 Pro 版的 Claude。

目前我也还没升 Max 版，据说是必弹 KYC，所以决定暂时先苟几天。后续有升级再来更新（如果有空的话（这篇断断续续写了一个月（社畜就这样orz。

续费的话，记得提前几天确认俩：一个是 ISP 的存续情况，一个是外区 Apple ID 的礼品卡余额。

前者不及时续费会释出，这样网络出口节点会变更不利于稳定性；后者是又得重来一次很麻烦，其实只要你保证账户里还有余额，第一次弄完之后，手机端的 Claude 都可以卸载了，防止误打开暴露 IP。要记得提早几天充进去哦，礼品卡有时候会售罄。
